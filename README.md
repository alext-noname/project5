# Домашні завдання

Настільний застосунок для обліку домашніх завдань. На вкладці «Головна» можна створювати дисципліни, змінювати їхній порядок, вести для кожної окремий список завдань, за потреби вказувати дедлайн, позначати виконання, редагувати та видаляти завдання. У налаштуваннях доступні світла й темна тема, а також українська, російська або англійська мова інтерфейсу. Списки завдань можна експортувати й імпортувати через буфер обміну між студентами. Застосунок має власну іконку, а встановлювач створює ярлики в меню «Пуск» та на робочому столі.

У Windows застосунок підтримує DPI-aware режим для чіткішого відображення на екранах із масштабуванням. Перезапустіть застосунок після зміни масштабу екрана.

## Вимоги

- Python 3.10 або новіший
- Tkinter (зазвичай входить до складу встановленого Python)

Зовнішні Python-пакети не потрібні.

## Запуск

Із папки проєкту виконайте:

```powershell
python app.py
```

Файл із даними створюється під час першого додавання дисципліни або завдання.

Також застосунок можна запустити через `run_app.bat`. Для цього потрібні встановлені Python 3.10+ і Tkinter.

## Установлення та ярлики через Inno Setup

1. Відкрийте `setup.iss` у Inno Setup 6 Compiler.
2. Виберіть **Build → Compile**.
3. Встановлювач `installer_output\HomeworkTrackerSetup.exe` створить ярлик у меню «Пуск». Ярлик на робочому столі можна увімкнути на етапі вибору додаткових завдань.

Встановлювач розміщує застосунок у профілі поточного користувача та не встановлює Python. На комп’ютері повинен бути Python 3.10+ з Tkinter.

## Тести

```powershell
python -m unittest discover -s tests -v
```

## Налаштування та обмін списками

Дедлайн необов’язковий. Якщо він зазначений, використовуйте формат `РРРР-ММ-ДД`, наприклад `2026-11-25`. Тема й мова зберігаються після перезапуску.

У налаштуваннях кнопка копіювання розміщує всі дисципліни та завдання в буфер обміну у форматі JSON. Вставлення імпортує список, об’єднуючи його з поточними даними: відсутні дисципліни й завдання додаються, а збіги за назвою дисципліни, назвою завдання та дедлайном пропускаються. Існуючі записи не замінюються. Буфер обміну має містити експорт саме цього застосунку.

## Розробка з AI-агентом і перевірка

AI-агенту було доручено створити настільний застосунок із головною вкладкою, введенням назви дисципліни та списком домашніх завдань. Агент допоміг підготувати моделі даних, локальне сховище, інтерфейс Tkinter і тести. Рішення щодо обсягу MVP і перевірку коду виконувала людина.

Code review виявив помилкове припущення в початковому завантаженні даних: кореневе значення JSON завжди є об’єктом. Додано перевірку схеми файлу. Тест `test_invalid_file_shape_is_reported` перевіряє, що непідтримуваний формат призводить до зрозумілої помилки, а не до `AttributeError`.

Перевірки охоплюють додавання, зміну та переміщення дисциплін, захист від повторних назв, порожній і некоректний дедлайн, додавання/зміну/видалення завдання, позначення виконання, міграцію старих записів із застарілим приоритетом, збереження теми й мови, а також перевірку імпорту/експорту й пропуску дублікатів. Тести запускаються наведеною вище командою.

## Обмеження MVP

- Дані зберігаються лише в локальному JSON-файлі; синхронізації й облікових записів немає.
- Сповіщень про строки немає; дедлайн вводиться вручну у форматі `РРРР-ММ-ДД`.
- Дисципліни й завдання доступні в одному профілі користувача на одному комп’ютері.
